## 检测方法

```text
HSV 蓝色: H 90–135, S ≥ 50, V ≥ 60
→ close/open
→ 轮廓面积 150–4000
→ bbox 12–100
→ 圆度 ≥0.2
→ hole ratio
→ score = circularity + 0.5 * hole
```

## 错误模式

1. **蓝色 Logo/图标与蓝环同色**
   - 单帧 HSV + 圆度会命中；
   - hole ratio 0.00 是有效判别：真蓝环 ≥0.31。

2. **蓝针叠在蓝色 UI 上**
   - 淘宝/支付宝蓝色区域会削弱圆环边界；
   - 当前样本中仍可检出，但需要更多蓝底样本。

3. **App 未真正打开**
   - 微博两张是主屏，不能作为 App 背景样本；
   - 基线必须校验页面身份，不能只看文件名。

## 决策

继续采用蓝色指针，并把规则收紧为：

```text
HSV 蓝色
+ hole ratio ≥0.20
+ 圆度 ≥0.5
+ 面积/尺寸
+ 上一位置 ROI
+ nudge diff 兜底
```

hole ≥0.20 可以排除这次的 2 个蓝色 Logo/图标；  
但会带来“找不到候选”的漏检，需要 nudge diff 兜底。

## 基线缺口

- 微博 2 张无效，需重新打开微博补采；
- 支付宝/盒马目前各只有 1 张真指针；
- 缺少：蓝色 UI 密集页、浅色页、深色页、贴边指针；
- 每个 App 建议至少 5–10 张，覆盖不同页面和指针位置。

## 下一步

1. 重采微博（确认标题/底部 tab 是微博）；
2. 补支付宝、盒马各 3–5 张；
3. 给 12 张有效图人工标注中心，计算 Median/P95 误差；
4. 用 hole≥0.2 + ROI + nudge diff 跑离线对比；
5. 若 P95 >3px，再考虑 Tiny Heatmap。
