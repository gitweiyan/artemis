## 5. 本次审计的边界（重要）

**已确认**：入口分流、动作汇聚点、Flash/Pro/Reflex 差异、Android 无 Session 主链、iOS 指针链、导入方向与违规点、测试与门禁数字。

**推断（静态得出，未动态验证）**：daemon 队列在并发下的实际行为、`ActionSession` 超时/取消的真实表现、iOS 指针校准对命中率的影响。

**未验证（需要真实环境）**：

- Android 真机的 Flash/Pro 动作、录制、Helper 回退。
- iOS 机台的 `ios-smoke` 六阶段与真实点击。
- daemon 并发任务、锁与回收。
- macOS / TV：当前不存在目标平台 Adapter。

任何后续报告都不得把本页的静态结论写成“真实设备已验证”。

## 6. 对后续 Phase 的直接输入

1. **Phase 1（Contracts）**：`CapabilitySet` 归属倒挂（`perception/base.py:8`、`control/base.py:8`）必须先由 ADR-001 决定 DTO 落点；坐标转换存在三套实现（`ScreenGeometry`、`utils/coordinates.py:316-326`、`actuators/adb.py:126-133`），ADR-002 前不要改行为。
2. **Phase 2（Registry/Builder）**：`drivers/factory.py:52-196` 的混杂是真实证据；`select_composition` 虽纯函数，但位于 `artemis.orchestration`（L2），需要迁到 L4。
3. **Phase 3（设备边界）**：真正的改造点在 `third_party/mobile_use/controllers/unified_controller.py:46-146`；仅改 `artemis/controllers/` 不会让 `DeviceSession` 成为唯一入口。
4. **Phase 4（Adapter/Profile）**：L4 对 `reflex/` 的 14 条导入边集中在 iOS 组合（`devices/ios_uvc.py`、`drivers/factory.py`、`drivers/ios/*`）。
5. **Phase 5（Safety）**：Flash 无前置安全网（`mcp/action_executor.py:160-215`），Pro 有（`validator/execution_loop.py:74`）；统一前先定义双策略。
6. **Phase 6（数据）**：动作 Span 已进 Data Engine（`action_executor.py:170`），但 iOS 的 `ActionResult.metrics` 是否完整落 Trace 尚未确认。
