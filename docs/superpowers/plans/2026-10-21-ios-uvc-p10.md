# iOS UVC P10: No Signal, No Click (frame health, frame age, incident taxonomy)

> **REQUIRED SUB-SKILL:** superpowers:executing-plans.

**Goal:** A frame that is black, stale, or never arrived must stop the chain with a named
incident (`uvc_no_signal` / `capture_timeout` / `stale_frame`) instead of reaching the
agent as a "successful screenshot" and turning into a blind or wrong click.

**Architecture:** `artemis/perception/incidents.py` owns the perception incident codes and
the health→code mapping. `IOSUvcHidDriver` stops bypassing `DeviceSession.snapshot()`
(which already gates on health), maps capture/perception failures onto
`ActionResult.incident`, and the pointer controller refuses to verify a click against a
frame older than its budget. The Validator classifies the codes like every other driver
incident.

**Spec:** `docs/ios-uvc-execution-plan.md` Phase 1 (IOS-UVC-12/15), Phase 4
(IOS-UVC-44), and the target doc §7/§8 (no signal → no click; frame age checked before
acting).

## Global Constraints

- A black frame must never be reported as a successful observation.
- A tap must never run on a frame older than the configured budget.
- Incident codes travel as data (`ActionResult.incident`), never as parsed prose.
- Android behavior and tests unchanged.

## Review Focus

- `capture_timeout` (no frame at all) and `uvc_no_signal` (a frame arrived, but black) are
  different failures with different fixes; do not collapse them.
- `Frame.captured_at` is a host monotonic stamp; a frame without one (test doubles, a
  future source) must skip the age check rather than fail.
- The observation path (`observe`) and the tap path must agree on the code for the same
  cause.
- `session.snapshot()` tries every source; a healthy second source must still win.
- The Operator's prompt has to say what to do, not just name the code.
