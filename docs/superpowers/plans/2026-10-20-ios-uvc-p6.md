# iOS UVC P6: iOS Runtime Config and Entry Point

> **REQUIRED SUB-SKILL:** superpowers:executing-plans.

**Goal:** Make `artemis run --platform ios` reach `IOSUvcHidDriver` deterministically: one
validated config object, one device descriptor with `mobile_platform=ios`, a startup log naming
the driver and its capabilities, and a clear error (never an Android fallback) when iOS config is
missing.

**Architecture:** `artemis/drivers/ios/config.py` owns env parsing/validation and the iOS
`DeviceContext`. The factory builds the session from it, the SDK's agent init skips the
ADB-only preflight for `DevicePlatform.IOS`, and the CLI selects the platform.

**Spec:** `docs/ios-uvc-execution-plan.md` Phase P5 (IOS-UVC-51) and
`docs/ios-artemis-fusion-status.md` §5 P6.

## Global Constraints

- `create_driver(ctx)` with `mobile_platform == "ios"` returns `IOSUvcHidDriver` or raises an
  error naming the missing setting; it never falls back to `AndroidAdbDriver`.
- Missing `ARTEMIS_ESP32_PORT` is a config error with remediation text.
- Android CLI/SDK behavior is unchanged (`--platform` defaults to android).
- UVC stays on-demand single-frame; no resident ffmpeg process.

## Review Focus

- Defaults must reproduce the measured rig: crop `736,53,1185,1027`, frame 449x974, screen
  1080x2400, pointer gain 1.8.
- A malformed env value must fail loudly at config construction, not deep inside a capture.
- `Agent.init()` must not overwrite an explicitly requested iOS platform with ANDROID.
- No `adb` binary may be required for an iOS run.
- Capability logging must not leak secrets (port path is fine; keys are not printed).
