# ios-taobao — 淘宝/闪购 iOS 操作经验

适用于：iPhone 通过 UVC 看屏 + ESP32 HID 鼠标/键盘操作淘宝或闪购。

## 硬约束

- 先确认支付总价，而不是商品标价。
- 配送单杯低价商品常被“起送价”挡住。例：古茗单杯 ¥4.5，但起送 ¥22。
- 目标“支付 <10 元”时：
  1. 先找无起送/低起送店；
  2. 找不到则切“自取”；
  3. 不凑单超过预算。
- 支付/Face ID/密码必须由用户完成；自动化只到支付确认页。

## 感知

- UVC 只抓单帧，不跑 30fps 常驻流。
- 中文文字定位用 PaddleOCR PP-OCRv6：
  - 全图 449×974 约 4.7s；
  - 顶部裁剪 449×280 约 2.2s；
  - 先裁剪目标区域再 OCR。
- OCR 返回 `rec_texts / rec_scores / rec_polys`，转 `TextBox` 后再 `locate_text`。
- 不要把 VLM 目测坐标当作精确 bbox；文字用 OCR，图标/大按钮用视觉/ER。

## 指针

推荐顺序：

```text
pointer.home()
→ 检测红环
→ 移动到目标
→ 立即抓帧（禁止 sleep）
→ 红环检测
   ├─ 失败 → Hough 圆环形状兜底
   └─ 误差 ≤8px → 立即 click
→ click 后抓帧 diff 验证
```

注意：

- 左上角 `(0,0)` 指针可能被裁切/淡出；可先移到可见锚点（如 120,120）。
- 目标落在红色 tab 上时，HSV 红环会融合；必须保留形状兜底。
- 无指针检测结果时绝不点击。

## 点击商品卡

小卡片容易误点相邻商品：

1. 用 OCR 得到商品标题和价格框；
2. 合并为卡片区域，点图片区中心，不点店铺标题/价格文字；
3. 点击前确认指针在卡片 bbox 内；
4. 点击后校验页面标题：
   - 含“珍珠奶茶” → 继续；
   - 含“桃胶/木薯/炖奶”等 → 立即返回；
5. 同一坐标连续两次未命中 → 停止重定位，不盲点。

实际误例：

```text
目标：珍珠奶茶|锡兰红茶
误点：桃胶木薯炖奶*2 ¥28.71
原因：整图目测 y 坐标，落入相邻卡片；未做 bbox/预检
```

## 手势

- 禁止从屏幕底部 100px 内起手向上滑，会被 iOS 识别为 Home 手势。
- 滚动从屏幕中部起手，幅度适中，滚动后立即抓帧确认。
- 页面被退回主屏时，重新打开淘宝后要重新搜索，不假设旧结果还在。

## 常见 UI 坐标（449×974，仅供参考）

| 元素 | 位置 |
|---|---|
| 顶部“闪购” | 约 (170,45) |
| 搜索框 | 约 (225,120) |
| 搜索按钮 | 约 (390,120) |
| 商品“选规格” | 卡片右侧按钮，需 OCR/bbox 定位 |
| 支付/结算 | 不预设坐标，必须抓帧确认 |

## 下单前检查

```text
[ ] 商品是珍珠奶茶，不是相邻商品
[ ] 规格：默认/少冰/糖度已确认
[ ] 商品价 + 配送费 - 优惠 ≤10
[ ] 起送价满足
[ ] 优惠券已尽量领取
[ ] 地址正确
[ ] 到支付确认页停止，等用户确认
```
