# ios-taobao — 淘宝/闪购 iOS 操作经验

适用于：iPhone 通过 UVC 看屏 + ESP32 HID 鼠标/键盘操作淘宝或闪购。

## 硬约束

- 先确认支付总价，而不是商品标价。
- 配送单杯低价商品常被“起送价”挡住。例：古茗单杯 ¥4.5，但起送 ¥22。
- 目标“支付 <10 元”时：
  1. 先扩大搜索/筛选，至少浏览多个店铺，记录每家的起送价、配送费、包装费；
  2. 不能只用当前可见的 3 家店就判断“配送模式无解”；
  3. 确实没有可行配送店时，才切“自取”；
  4. 不凑单超过预算。
- 结论纪律：区分“当前样本无解”和“全局无解”。写结论时必须说明样本范围。
- 支付/Face ID/密码必须由用户完成；自动化只到支付确认页。

## 感知

- UVC 只抓单帧，不跑 30fps 常驻流。
- 中文文字定位用 PaddleOCR PP-OCRv6：
  - 全图 449×974 约 4.7s；
  - 顶部裁剪 449×280 约 2.2s；
  - 先裁剪目标区域再 OCR。
- OCR 返回 `rec_texts / rec_scores / rec_polys`，转 `TextBox` 后再 `locate_text`。
- 不要把 VLM 目测坐标当作精确 bbox；文字用 OCR，图标/大按钮用视觉/ER。

## 指针

推荐顺序：

```text
pointer.home()
→ 检测红环
→ 移动到目标
→ 立即抓帧（禁止 sleep）
→ 红环检测
   ├─ 失败 → Hough 圆环形状兜底
   └─ 误差 ≤8px → 立即 click
→ click 后抓帧 diff 验证
```

注意：

- 左上角 `(0,0)` 指针可能被裁切/淡出；可先移到可见锚点（如 120,120）。
- 目标落在红色 tab 上时，HSV 红环会融合；必须保留形状兜底。
- 无指针检测结果时绝不点击。

## 点击商品卡

小卡片容易误点相邻商品：

1. 用 OCR 得到商品标题和价格框；
2. 合并为卡片区域，点图片区中心，不点店铺标题/价格文字；
3. 点击前确认指针在卡片 bbox 内；
4. 点击后校验页面标题：
   - 含“珍珠奶茶” → 继续；
   - 含“桃胶/木薯/炖奶”等 → 立即返回；
5. 同一坐标连续两次未命中 → 停止重定位，不盲点。

实际误例：

```text
目标：珍珠奶茶|锡兰红茶
误点：桃胶木薯炖奶*2 ¥28.71
原因：整图目测 y 坐标，落入相邻卡片；未做 bbox/预检
```

## 滚动

- **优先用键盘滚动**：`Down` / `Up`，必要时 `PageDown` / `PageUp`。
- 避免用鼠标/手指向上滑：从屏幕底部起手会被 iOS 识别为 Home 手势。
- 如果键盘滚动无效、必须用指针拖动：
  - 从屏幕中部起手；
  - 禁止从底部 100px 内起手；
  - 小幅度、多次滚动，每次滚动后立即抓帧确认。
- 页面被退回主屏时，重新打开淘宝后要重新搜索，不假设旧结果还在。

## 反例：过早判定“无解”

曾只看到牧白（起送 ¥25）、古茗（起送 ¥22）、贡茶（起送 ¥40），就写下“配送模式无解”。  
这是错误归纳：正确说法是“这 3 家在当前条件下无解”，并不代表其他店没有低起送或免配送费方案。

改进：

- 用平台筛选/搜索继续找更多店；
- 记录候选店的起送价与配送费；
- 至少覆盖一屏以上或筛选结果，再下结论；
- 结论里写明“已检查 N 家，均不满足”，而不是“无解”。

## 下单前检查

```text
[ ] 商品是珍珠奶茶，不是相邻商品
[ ] 规格：默认/少冰/糖度已确认
[ ] 商品价 + 配送费 - 优惠 ≤10
[ ] 起送价满足
[ ] 优惠券已尽量领取
[ ] 地址正确
[ ] 商品卡由 OCR bbox 定位，未使用整图目测坐标
[ ] 滚动优先用键盘，未从屏幕底部上滑
[ ] 到支付确认页停止，等用户确认
```
