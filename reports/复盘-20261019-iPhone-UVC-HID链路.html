4根因分析

R1 · 单 USB-C 口 + Hub 数据路径不可靠 环境原因

触发条件与生命周期：iPhone 只有一个 USB-C 口，要同时接 UVC（HDMI 采集）和 ESP32 HID，只能经 Hub。Hub 的 HDMI 通道正常，但 ESP32 所在的 USB 数据口/线不通：直连 mounted=1，经 Hub mounted=0。用户后来确认是 ESP32↔Hub 的 USB 线问题，换线后复合设备也能挂载。

证据：T9 烧录后 mounted=0；T10 直连 mounted=1 suspended=0 mouse=1 keyboard=1 touch=1；用户 09:53:59/10:00:48 的回复（session-a5d612bb:seq=896, seq=1057）。

关联问题：P1、P2 ｜ 关联改进项：I1、I7

R2 · iOS 的输入模型：无外部 digitizer、相对鼠标、指针显示依赖辅助触控状态 环境原因

触发条件与生命周期：iOS 只接受键盘和鼠标/触控板；鼠标必须开 AssistiveTouch，指针是相对、带加速度的系统 overlay。本次在辅助触控未真正生效时，UVC/HDMI 抓帧里看不到这个指针（move 20 0 前后 diff 为 0）；用户开启后，同一路 UVC 出现了 17×20 的指针 blob。也就是说，UVC 本身可以承载指针，但必须先确认辅助触控已生效。叠加 USB 挂起（suspended=1）时，键盘/鼠标报文也发不进去。

证据：T17 touch tap 0 像素变化；T24 UVC 指针不可见/盲点失败；T28 开启辅助触控后指针 blob 出现；session-a5d612bb:seq=1784, seq=2269, seq=2643。

关联问题：P3、P4、P7 ｜ 关联改进项：I2、I6、I7、I8

R3 · 固件/采集工具链没有按 HID 语义处理 Agent 框架原因

触发条件与生命周期：复合 HID 的 keyboard/mouse 最初带 Report ID 3/2 且声明为 boot protocol，iOS 能枚举但报文不生效；改成无 Report ID 后键盘立刻可用。鼠标侧 home 以 2ms 间隔连发 50 个报文，而 HID 端点轮询是 10ms，大量报文被丢；cmd.c 的 move 把 dx/dy 强转 int8_t，超过 127 会回绕。UVC 采集又是每帧一个 ffmpeg 进程（约 850ms/帧），没有持久流。

证据：固件 mobile-agent-demo/esp32-hid/firmware/main/hid_descriptor.h:13-14（Report ID 0）、hid_descriptor.c:59-67、hb_mouse_kb.c:21（hid_mouse_move）、cmd.c:109-121（home/move）、cmd.c:138（keymod）；UVC 单帧耗时见 session-a5d612bb:seq=286, seq=1737。
